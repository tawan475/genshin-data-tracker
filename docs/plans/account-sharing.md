# Account sharing (proposal, 2026-10-25)

Status: **approved 2026-10-25 as written and built** (README "Account sharing"). Not built yet: the staff user page's lists (§8) and the shared-account count in the Delete user dialog (§9).

Goal: two (or a few) people follow one Genshin account. The owner shares it
by username from the account's Manage page (`/app/a/:id/settings`), under a
new **Account sharing** section listing everyone who can see it.

## 1. Roles

Two roles besides the owner. One plan, one set of marks per Genshin account:
members see and change the *same* planner, achievements and anecdotes as the
owner (that is what "sharing one game account" means; per-person plans would
need every planner table keyed by user too).

| Can… | Viewer | Editor | Owner |
|---|:-:|:-:|:-:|
| See every page, export the zip | ✓ | ✓ | ✓ |
| Upload (website Import, own irminsul, own user key) | | ✓ | ✓ |
| Planner (targets, goals, Done, tasks, resin, inventory edits, crafting) | | ✓ | ✓ |
| Achievement / anecdote marks, Traveler, wish import (link, UIGF, paimon) | | ✓ | ✓ |
| Name / UID / server, live-sync switch, delete chart points | | | ✓ |
| Account import key, delete snapshots / Discard live | | | ✓ |
| Sharing (invite, change role, remove), delete the account | | | ✓ |
| Leave | ✓ | ✓ | |

Destructive or identity-changing actions stay with the owner. For the
two-people case the owner invites the other as **Editor**.

## 2. Invite → accept

Direct add would put an account in someone's switcher without asking, so:

1. Owner types an exact username + role → **Invite**. `404 user_not_found`
   for an unknown name (usernames are already discoverable at sign-up, so
   hiding it buys nothing). Not yourself, not an existing member.
2. The invitee sees it at once (live event) on Home (`/app`) as an
   **Invitations** row (account name, UID, owner, role · Accept / Decline)
   and a dot on the switcher. Nothing is visible to them before Accept.
3. Pending invites expire after 14 days (maintenance cleans them); the owner
   can cancel one.

Limits: 8 members per account, 20 pending invites per owner (stops spam).

Revoke: owner removes a member (takes effect on the member's next request:
access is read from D1 per request, see §4; their socket gets an `accounts`
event so the switcher drops it at once). Leave: a member removes themselves.
Role changes take effect the same way. Ownership transfer: not in v1.

## 3. What a member sees

- **Switcher / Home:** shared accounts in their own group "Shared with me",
  each with the owner's username and a role badge (`UiBadge`). Order as today.
- **Account pages:** a small `Viewer` / `Editor` badge in the top bar next to
  the UID. Viewers get the read-only mode staff Inspect already has
  (`useReadOnly()`), so every write control that checks it hides; editors see
  the owner-only controls hidden (Manage shows Details read-only, no key,
  no delete; Snapshots has no delete).
- **Manage → Account sharing** (everyone): Owner row first, then members
  (username, role, since; pending invites dimmed with "Invited"). Owner: role
  select + Remove per row, and an *Add* row (username field, role
  `UiSegmented`, Invite). Members: the list and **Leave**.
- **Devices:** an irminsul device's "Always this account" list includes
  accounts shared with you as Editor.

## 4. Schema (migration 0029, CREATE only)

```sql
CREATE TABLE account_members (
  account_id  INTEGER NOT NULL REFERENCES genshin_accounts(id) ON DELETE CASCADE,
  user_id     INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role        TEXT    NOT NULL,            -- 'viewer' | 'editor' (checked in code)
  invited_by  INTEGER,                     -- no FK: label kept if they go
  created_at  INTEGER NOT NULL,
  accepted_at INTEGER,                     -- NULL = pending invite
  PRIMARY KEY (account_id, user_id)
);
CREATE INDEX account_members_user ON account_members (user_id, accepted_at);
```

Only `CREATE TABLE` / `CREATE INDEX`, so `migrations.test.ts` passes without
a `HAND_WRITTEN` entry; generated by drizzle-kit from `worker/db/schema.ts`.
`genshin_accounts.user_id` stays the owner — no parent table is touched.

**Access check.** `loadOwnedAccount` / `assertOwnsAccount` (24 call sites,
mostly `routes/accounts.ts`, `routes/progress.ts`, `routes/wishes.ts`,
`routes/live-sync.ts`) become `loadAccount(db, userId, accountId, need)` with
`need` = `'view' | 'edit' | 'own'`, in **one** query (no new round trip; the
`D1 cost` tests pin that):

```sql
SELECT a.*, CASE WHEN a.user_id = ?1 THEN 'owner' ELSE m.role END AS access
FROM genshin_accounts a
LEFT JOIN account_members m
  ON m.account_id = a.id AND m.user_id = ?1 AND m.accepted_at IS NOT NULL
WHERE a.id = ?2 AND (a.user_id = ?1 OR m.user_id IS NOT NULL)
```

No row → 404 (as today, a stranger can't tell it exists); too low a role →
403 `account_read_only` / `owner_only`. Routes that read inside a bigger
batch (bootstrap, import lookup, irminsul) get the same `LEFT JOIN`. A test
walks every `/api/accounts/:id/*` route as a stranger (404), viewer (reads
only) and editor (no owner routes), so a new route can't forget the check.

**Account list / bootstrap.** Owned ∪ accepted memberships in the existing
batch; `AccountResponse` gains `access: 'owner' | 'editor' | 'viewer'` and
`owner?: string` (username, members only) — append-only. The list ETag
(`bodyEtag`, a hash of the answer) covers membership for free, since `access`
and `owner` are in the answer. Pending invites ride along as `invitations` in the bootstrap.
The device caches (`boot-cache`, IndexedDB `gdt-data`) keep shared accounts
like owned ones and drop an account's data when it leaves the list.

## 5. Live updates and notifications

`notifyUser(ownerId)` on every write path becomes `notifyAccount(accountId)`:
the owner plus accepted members whose `users.live_since` is set, read inside
the write's existing D1 batch (one extra `SELECT` in the batch, not a round
trip). Planner writes keep `x-gdt-tab`. Sharing changes send `{type:
"accounts"}` to both sides (invite, accept, decline, role, remove, leave),
which re-reads the list (`GET /api/accounts` with ETag). No email (paused).

## 6. Uploads

- **Website Import / account key:** website import needs `edit`; the
  account's own import key stays owner-made but works for any upload as today.
- **User-scoped key / irminsul sign-in "Auto by UID"** (`services/upload-as.ts`):
  the file's `gi_player.uid` → 1) the uploader's **own** account with that UID;
  2) else exactly one account **shared with them as Editor** with that UID;
  3) else a viewer-only match → 403 `shared_read_only` (no silent duplicate
  account); 4) else a new account, as today. "Always this account" may name a
  shared Editor account; losing the role makes those uploads 403 until the
  owner re-adds them or the device picks another target.
- Live sync journals belong to the account, so an editor's irminsul feeds it
  like the owner's (the live-sync switch is the owner's).

## 7. Quotas

Everything stored under an account counts for its **owner** — storage quota
(200 MB), daily snapshots/bytes and gdt-live bytes — because the queries
already join `genshin_accounts.user_id`. An editor's upload to a shared
account uses the owner's allowance (shown as the owner's 413/429). Burst
limiters stay per key / per account. The owner can remove an editor who
burns it.

## 8. Staff

Inspect is by account id and unchanged. The staff user page lists, per user,
accounts they own (with member count) and accounts shared with them (role,
owner); private fields of members follow `users.view_private` as elsewhere.
Membership changes are not staff actions, so no `admin_audit` rows; staff
removing a member (if wanted later) would be audited.

## 9. Deleting

- **Account deleted** (owner, or staff purge): `account_members` rows go with
  it (FK cascade on a new table — the cascade is the point here); members get
  an `accounts` event. gdt-live cleanup is unchanged.
- **Owner deletes their user:** their accounts go, shared ones included; the
  Delete user dialog says "N accounts shared with others are deleted for them
  too". The last-Owner rule is untouched.
- **Member deletes their user:** their memberships cascade away; the account
  is untouched.
- Planner/marks rows an editor made stay with the account (they are the
  account's, not the editor's).

1. Migration 0029 + schema + `loadAccount` + route matrix test (stranger /
   viewer / editor / owner on every account route).
2. Sharing routes: `GET/POST /api/accounts/:id/members`,

   /api/invitations/:accountId/accept|decline`; account list `access`/`owner`,

3. Upload routing (§6) with tests for each precedence step; quota counted on

4. UI: Manage section, Home invitations, switcher group, read-only modes,
   Devices targets. All 15 locales.
5. Staff user page lists, Delete user warning.
